# Release notes - 0.3.0 "Experience, identity & persistence"

> **Status: draft** - pending the 0.3.0 gates (CI green, `v0.3.0` image push with digests, `kind`
> smoke transcript). Placeholders below (`<digest>`, transcript) are filled at cut time.
> Plan: [docs/release-plan-0.3.0.md](../release-plan-0.3.0.md).

0.2.0 made Logistics OS **distributable**. 0.3.0 makes it **usable**: a browser console for operators,
real authentication (OIDC + a local fallback), and the first **system-of-record** with a transactional
outbox so MDM can write to PostgreSQL and publish consistently.

## Highlights

- **Ops console (React + TS + Vite)** - [`web/`](../../web/README.md) is a single-page app served by
  nginx. It talks **only** to `bff-ops` (ADR-0022): dashboard (shipment/alert counts, source health,
  edition badge), shipment list + detail, operator-gated "Notify customer", and Alerts.
- **Identity & access (ADR-0020)** - new [`platform:security`](../../platform/security/README.md)
  auto-configures a stateless OAuth2 resource server. `mode=oidc` validates Keycloak-issued JWTs
  (lazy JWKS); `mode=local` (default) issues/validates HS256 dev tokens from `users.json` via
  `POST /auth/login`. A `TenantContextFilter` binds `TenantContext` and rewrites `X-Tenant-Id` from the
  `tenant_id` claim (403 if absent). Roles `viewer`/`operator`/`admin`; `@PreAuthorize("hasRole('OPERATOR')")`
  guards the one-click actions. Wired into `mdm`, `ingest-gateway`, `control-tower`, and `bff-ops`;
  bff-ops **relays the caller's bearer token** to upstreams.
- **Persistence & transactional outbox (ADR-0021)** - new
  [`platform:persistence`](../../platform/persistence/README.md) ships `JdbcOutboxRepository` +
  `JdbcDedupeStore` and shared migrations (`V900__outbox.sql`, `V901__idempotency_keys.sql`). **MDM**
  becomes a PostgreSQL system-of-record under the `jdbc` profile: golden records are upserted with
  optimistic versioning and the change event is enqueued in the **same transaction**, then dispatched
  by a scheduled relay. Without the profile, MDM keeps the in-memory registry + direct publish.
- **Reference stack** - local compose and the k8s base gain **PostgreSQL 16**, **Keycloak** (realm
  import: `logistics-os-web` client + roles + dev users), and the **web** console.
- **Release automation** - `web.yml` builds/typechecks the SPA; `images.yml` also publishes
  `ghcr.io/logistics-os/web`.

## Authentication

- **Local (dev/CI)** - `POST /auth/login {"username":"ops","password":"ops"}` returns an HS256 token.
  Dev users: `admin`/`admin`, `ops`/`ops` (operator), `viewer`/`viewer`.
- **OIDC (production/SaaS)** - set `LOGISTICS_SECURITY_MODE=oidc` and
  `LOGISTICS_SECURITY_OIDC_ISSUER_URI`; the reference Keycloak realm lives in
  `ops/k8s/apps/keycloak.yaml` / `ops/local-compose/keycloak/`. The SPA (ADR-0022) uses Authorization
  Code + **PKCE**.

## Persistence / MDM

- Activate with `SPRING_PROFILES_ACTIVE=jdbc` (+ `MDM_DB_URL`/`MDM_DB_USER`/`MDM_DB_PASSWORD`).
  Flyway applies `db/migration/V1__mdm.sql` and the shared `io/logisticsos/persistence/migration`
  (reserved `V900+`).
- Upserts are idempotent (unchanged canonical JSON is a no-op); each change bumps `version`, updates
  `mdm_golden_record` and inserts an `outbox_record` row atomically; a scheduled relay dispatches to
  the entity topic. Docker Compose sets up the `mdm` database automatically.

## Known limitations

- Service images in `ops/k8s` are not yet retagged to `0.3.0` (bumped at cut); `web` is `0.3.0`.
- Kafka/Postgres/Keycloak are single-instance (no HA); `logistics-os-secrets` holds **dev defaults**.
- MDM is the only system-of-record so far; other services still keep in-memory/derived state.
- Local HS256 tokens are single-issuer; OIDC multi-tenant claim mapping is a single hardcoded
  `tenant_id` in the reference realm.
- Entitlement enforcement remains **soft** (permissive) - see [licensing.md](../product/licensing.md).
- No live image push / `kind` smoke run has been executed as part of authoring this draft.

## Upgrade / rollback

- No migrations affect existing state (MDM gains a new optional Postgres mode; in-memory mode is
  unchanged and remains the default without the `jdbc` profile).
- Source rollback = revert the release commit/tag; images are immutable per digest.
